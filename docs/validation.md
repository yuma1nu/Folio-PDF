# 実装と検証の記録

対象：Folio PDF 0.1.0 / Windows 11 x64。

## 0.1.3：ネットワーク共有の監視エラー対策

- PDFを開いた後の `fs.watch` の非同期errorイベントが未処理になっていた。起動時のtry/catchだけでは捕捉できず、ネットワーク共有で読み込みが成功しても別途エラーが表示される可能性がある。
- 監視エラーを個別に捕捉し、5秒間隔のstatベースの更新確認へ切り替える。PDFの読み込み・操作は継続する。
- 切断時のゼロ情報は無視して最後に取得できた更新情報を保持し、再接続時の誤通知を避ける。文書を閉じると定期確認も終了する。
- 同期的な開始エラー、非同期UNKNOWN、重複エラー、切断・再接続、終了後の遅延エラーを自動テストで確認。
- 実際の会社のネットワーク共有では再現確認できていないため、今回の報告の原因と断定はしない。エラーダイアログの文言との照合が必要。
- 配布先は `release/0.1.3/`。旧版は保持。

## 0.1.2：上部ツールバーの整理

- 「ライブラリ ＞ ファイル名」の行を削除し、PDF表示領域を縦に42px拡張。
- サイドバー開閉ボタンと保存状態を閲覧用ツールバーに統合。ホームでは開閉ボタンだけの簡素な行を表示。
- 配布版の検証で、行の削除、表示領域の位置、保存済み／未保存の状態表示、最小幅800pxでの操作部品の配置を確認。
- 配布先は `release/0.1.2/`。旧版の実行ファイルは保持。

## 0.1.1：左メニューの折り畳み修正

- PDF.jsの `.sidebar` に設定された180pxの最小幅がアプリの左メニューへ混入していた。アプリ側のクラス名を分け、ライブラリのスタイルが適用されないよう修正。
- 折り畳み時は48px幅とし、開く・検索・設定のアイコンを中央に配置。再展開時は元の幅へ戻す。
- 配布版の検証に、ライト・ダークでの実寸48px、本文領域の拡張、アイコンのはみ出し、再展開時の幅復元の確認を追加。
- 配布先は `release/0.1.1/`。既存の0.1.0実行ファイルはそのまま残す。

## 実装済み

- Electronのサンドボックス・context isolationと用途を限定したpreload API。
- PDFの選択・ドロップ・起動引数・タブ・別ウィンドウ・移動。
- PDF.jsによる文字選択、連続スクロール、サムネイル、ページ移動、全文検索。
- 25〜1600%の拡大、幅合わせ、ページ全体表示、マウスポインター基準のCtrl+ホイール、パン。
- 部分的な詳細キャンバス、既存表示の一時利用、描画キャンセル、ピクセル密度変更への対応。
- 並べ替え・削除・回転、複数選択、元に戻す・やり直す。
- 別名保存・選択ページ抽出・指定順の結合。PDF生成はWorkerで実行。
- 既存ファイルを保護する一時ファイル経由の保存。外部更新時は開いているバイト列を保持。
- 印刷専用ページの生成、標準印刷ダイアログの呼び出し、準備キャンセル。
- ライト・ダーク・OS追従、設定保存、最近のファイルと閲覧位置・セッションの復元。
- PDF関連付けを登録するWindows用インストーラー。

## 自動検証

| 検証 | 内容 |
| --- | --- |
| TypeScript | `tsc --noEmit` |
| 単体テスト | ページ範囲の厳密な検証、複数ページ移動、回転・削除・原本の不変性 |
| Electronスモーク | ライト／ダーク画面、全文検索、1600%詳細描画、並べ替え・回転・削除・undo、別名保存結果、ウィンドウ移動 |
| 統合テスト | ページ抽出、指定順の結合、印刷ページと紙面サイズ、再起動後のタブ・テーマ復元 |
| 品質テスト | A0相当のベクターPDF、1600%、詳細キャンバスの画面密度、連続ズーム／パン後の更新 |
| 高DPI | 200%相当で、詳細キャンバスがCSSサイズの約2倍の物理解像度になることを確認 |
| 配布版 | unpacked実行ファイルでの起動、PDF表示、検索、詳細描画、Workerによる文書検査と編集 |

印刷テストは最終的なプリンターへの受け渡しをChromiumのPDF出力に置き換えている。物理プリンターへの出力は行っていない。

生成した検証用ファイルとスクリーンショットは `test-results/` に保存する。ユーザーの通常プロファイルとは別のデータ領域を使う。

## 数値と評価範囲

- 開発用実行ファイルのホーム初回表示は、この環境のスモーク実行で約0.4秒。単一環境での参考測定であり、コールド起動の保証値ではない。
- 配布版のA0相当の検証PDFでは、プロセス起動から最初のキャンバス表示まで約1.3秒。実際の複雑な図面の高精細化完了時間を示す数値ではない。
- 1600%・DPR 1の詳細キャンバスは2362×1669px（CSS幅約2362px）。DPR 2では2468×1704px（CSS幅約1234px）。全ページをこの倍率で画像化せず、詳細領域を必要な密度で描画している。
- 仕様書の全性能目標、特に各代表ケース20操作以上の95パーセンタイル評価は未実施。

## 実機・実文書での追加確認が必要な項目

- 実際に利用する図面での細線・ハッチング・日本語埋め込みフォント・透明度の比較。
- 500ページ級や複雑な図面を長時間使用したときのメモリピークと描画停止時間。
- 実モニター間の移動とWindowsの表示倍率変更（自動テストは強制DPIでの検証）。
- 実プリンターの用紙・倍率・余白・両面・ドライバー固有設定。印刷画像は初期版150dpi。
- Windows設定からの既定PDFアプリへの変更、エクスプローラーからのドロップとダブルクリックの実操作。
- 各種暗号化PDF・電子署名PDF・破損PDFとの互換性。

アプリはローカル処理のみで利用できる。初期版の未対応範囲と原本保存についてはREADMEおよび仕様書を参照すること。
