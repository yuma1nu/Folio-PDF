# PDFViewer 仕様書

- 作成日：2026年11月8日
- 版：1.2（実装前仕様・図面向け高精細描画を追加）
- 対象：Windows 11 / Electron・React・TypeScript
- アプリ名：PDFViewer（仮称）
- 確定事項：ユーザー指定の機能・OS・ウィンドウ操作・参考画像
- 推奨案として採用：保存、検索、結合・分割、UI寸法、性能目標などの詳細

## 1. 目的

広告や不要な機能を排し、日常のPDF閲覧とページ整理を少ない操作で行えるデスクトップアプリを作る。最初のページを素早く読めること、閲覧中に操作が止まらないことを重視する。

図面の細線・寸法文字・ハッチングを拡大して確認できる描画品質を、応答性と並ぶ必須要件とする。操作中の一時的な低解像度表示は許容するが、操作停止後は現在の表示範囲を適切な解像度で再描画し、粗い表示のまま確定しない。

PDFは端末内で処理する。アカウント登録、クラウド同期、PDFの外部送信は不要とする。

## 2. 対象環境と配布

- Windows 11、初期配布はx64向け。
- 通常のセットアップ実行ファイルで配布する。
- 利用者によるNode.jsや開発ツールのインストールは不要。
- インストーラーでPDFの関連付け候補として登録する。既定アプリの変更はWindowsの設定に従い、強制変更しない。
- インストール・更新時を除き、閲覧・編集・保存・印刷はネット接続を必要としない。
- 初期版は手動更新。常駐プロセスや起動時のネットワーク確認は設けない。

## 3. 初期版の機能範囲

| 分類 | 対応内容 |
| --- | --- |
| 閲覧 | 開く、連続スクロール、ズーム、幅合わせ、ページ全体表示、文字選択・コピー |
| ページ移動 | サムネイル、ページ番号入力、前後ページへ移動 |
| 検索 | 現在のPDF全体を対象とした文字検索、強調表示、一致箇所への移動 |
| ページ整理 | PDF内の並べ替え、削除、90度単位の回転、元に戻す・やり直す |
| 結合 | 複数PDFを指定順に1つにする |
| 分割・抽出 | ページ範囲または選択ページから別PDFを作る |
| 印刷 | Windowsの標準印刷ダイアログを利用 |
| ウィンドウ | 複数タブ、タブを別ウィンドウへ移動、別ウィンドウから取り込み |
| 日常操作 | ダブルクリック起動、ドラッグ＆ドロップ、閲覧位置とセッションの復元 |
| 外観 | ライト・ダーク・OS設定に合わせる、の切り替え |

初期版に含めない機能：OCR、複数PDF横断検索、本文の直接編集、注釈の新規作成、電子署名、フォーム入力・保存、別PDFのページへの差し替え・挿入、クラウド連携、独自印刷プレビュー。

- 参考画像：`reference/redia-01.jpg`、`reference/redia-02.jpg`
- 参考画像は開発時のローカル資料であり、公開リポジトリ・ソース配布には含めない。
- 白い本文領域と、暖かみのある淡いグレーのサイドバー。
- 細く淡い境界線、影を抑えた平坦な画面。
- 濃いグレーの文字と線画アイコン。強い色は検索結果・フォーカスなどに限定する。
- ボタンは小さめで、通常時の装飾を抑え、ホバー・選択時に背景を付ける。

### 4.1.1 テーマ切り替え

- 設定の「外観」で「ライト」「ダーク」「OS設定に合わせる」を選択できる。初期値は「OS設定に合わせる」。
- ダークでもrediaの余白・細い区切り線・控えめな操作部品を踏襲する。
- タブ、ツールバー、サイドバー、検索結果、ページ整理、アプリ内ダイアログ、ツールチップ、空画面、エラー表示をテーマに対応させる。
- PDF本文とサムネイルの紙面は元の色で表示し、色反転や画像への暗色フィルターは適用しない。印刷・保存結果にもテーマを反映しない。
- 設定変更は開いている全ウィンドウへ即時反映する。「OS設定に合わせる」では起動中のOSテーマ変更にも追従する。
- 選択した設定を保存し、次回起動時は最初の描画から適用する。ウィンドウを新しく開く際もテーマのちらつきを抑える。
- OS標準のファイル選択・印刷ダイアログはOS側の外観に従う。アプリ独自テーマとの完全な一致は要求しない。
- 両テーマで検索の一致・現在の一致・選択・フォーカス・無効状態を識別できるようにする。通常文字は背景とのコントラスト比4.5:1以上を目標に調整する。

### 4.2 通常の閲覧画面

```text
┌─────────────────────────────────────────────────────────────┐
│ PDFViewer   [資料A.pdf ×] [資料B.pdf ×]             最小化等 │
├─────────────┬───────────────────────────────────────────────┤
│ 開く        │  ページ 3 / 24   − 100% ＋  幅合わせ          │
│ 検索        │  ページ整理   結合   保存…   印刷   …         │
├─────────────┼───────────────────────────────────────────────┤
│ サムネイル  │                                               │
│ [ 1ページ ] │              PDF本文                          │
│ [ 2ページ ] │                                               │
│ [ 3ページ ] │                                               │
│             │                                               │
├─────────────┤                                               │
│ 設定        │                                               │
└─────────────┴───────────────────────────────────────────────┘
```

- 左ペインは初期幅220px。160〜360pxで幅変更でき、折り畳み時はアイコンだけの48px幅とする。再展開時は折り畳み前の幅に戻す。
- 左ペインは「サムネイル」と「検索結果」を切り替える。
- ファイル名はタブに表示し、「ライブラリ ＞ ファイル名」の重複した行は設けない。サイドバー開閉・保存状態は閲覧用ツールバーにまとめる。
- 本文は縦方向の連続スクロール。現在ページのサムネイルを強調する。
- 異なる用紙サイズ・縦横が混在するPDFも、倍率にかかわらず全ページを共通の左右中央線に揃える。横スクロール領域は最も広いページ以上の幅とし、低倍率では表示領域の幅を下限にする。
- ウィンドウ幅が狭い場合は低頻度操作を「…」にまとめる。
- 初期ウィンドウは1200×800程度、最小サイズ800×600。画面に収まるよう補正する。
- 未保存の変更があるタブには印を付ける。ファイル名が長い場合は省略し、ツールチップでフルパスを示す。
- ファイル未選択時は「PDFを開く」「ここにドロップ」と最近開いたファイルを表示する。

### 4.3 ページ整理画面

- 中央を複数列のサムネイル一覧へ切り替える。
- クリックで単一選択、Ctrlで追加選択、Shiftで範囲選択。
- 選択ページをドラッグして並べ替える。複数選択時は相対順序を保持する。
- ドラッグ以外にも「前へ／後ろへ移動」を用意する。
- 上部に「左回転」「右回転」「削除」「選択ページを保存」「元に戻す」「完了」を表示する。
- 「完了」は閲覧画面へ戻る操作であり、ファイルへの保存ではない。

## 5. ファイルを開く・タブとウィンドウ

- ファイル選択ダイアログ、PDFのドラッグ＆ドロップ、OSから渡されたファイルパスに対応する。
- 複数ファイルは指定された順番で開く。非PDFファイルは理由を表示して除外する。
- 通常の新規オープンは、最後に操作したウィンドウの新しいタブに追加する。
- 設定で「タブで開く／別ウィンドウで開く」の既定動作を選択できる。初期値はタブ。
- タブメニューの「別ウィンドウへ移動」で、そのPDFを新しいウィンドウへ移す。
- 別ウィンドウでは「別のウィンドウへ移動」から移動先を選び、タブとして戻せる。
- 移動時はページ位置、倍率、検索語、選択、編集状態、元に戻す履歴を維持する。元のタブは移動完了後に閉じる。
- タブのドラッグによるウィンドウ間移動は初期版の必須要件としない。
- 同一パスが既に開かれている場合は既存タブへ移動し、編集状態の競合を避ける。
- 追加起動は既存アプリへ引数を渡し、既定の開き方に従う。
- 最後のタブを閉じたウィンドウはホームを表示する。空になった移動元ウィンドウも同様。

## 6. 閲覧・サムネイル

- 初回表示は幅合わせ。図面確認のため倍率は25〜1600%、幅合わせ、ページ全体表示に対応する。高倍率時はページ全体を巨大な画像にせず、表示範囲を高精細に描画する。
- ページ番号は1始まり。入力値が範囲外の場合は移動せず、入力欄にエラーを示す。
- サムネイルをクリックすると該当ページへ移動する。
- 表示中のページとその近傍を優先描画する。サムネイルも表示範囲から生成する。
- 並べ替え・削除後のページ番号は現在の並び順を表す。
- ページに固定IDを持たせ、並べ替え後も閲覧対象を追跡する。閲覧中のページを削除した場合は次ページ、なければ前ページを表示する。
- PDF内のページリンクは移動に対応する。外部リンクはユーザー操作時のみ既定ブラウザーで開き、許可するURL形式を限定する。

### 6.1 描画品質と表示解像度

- ベクターの線・文字は、元PDFの描画情報から現在の倍率に合わせて再描画する。低倍率で生成したページ画像の引き伸ばしを最終表示にはしない。
- 最終描画は、表示領域のCSSピクセル数に実効的な `devicePixelRatio` を掛けた物理ピクセル数を基準にする。PDFの倍率を重複して掛けず、OSの表示倍率とディスプレイ密度を反映する。
- 異なる表示倍率のモニターへの移動、ウィンドウのリサイズ、幅合わせ、ページ回転でも必要解像度を再評価する。
- 細線、破線、曲線、ハッチング、日本語の寸法文字、透明な重ね合わせ、埋め込みフォントを検証対象とする。タイル境界による線の切れ・二重描画を生じさせない。
- 元PDFが画像だけの場合は元画像の解像度が上限となる。失われた細部の復元やAI補完は行わず、画像本来の情報を表示する。
- 検索強調・文字選択・リンク領域はPDF座標に基づいて管理し、拡大・回転・描画差し替え後も本文からずれないようにする。

### 6.2 操作中の即時表示と高精細表示への更新

1. ズーム・スクロール・パンの入力には既存の描画とキャッシュを使って直ちに追従する。新しい高精細描画が完了するまで入力や画面更新を待たせない。
2. 既存画像は新しい座標へ一時変換して表示する。この間のぼけや、未描画領域の暫定表示は許容する。既に高精細なキャッシュがある領域は優先して再利用する。
3. 操作停止後は現在の表示範囲を優先して再描画する。連続入力の集約時間は初期値100〜150ms程度とし、実測で調整する。長時間の操作中も余力があれば見えている領域を更新する。
4. 新しい描画は別バッファで完成させ、文書・回転・倍率・表示位置が現在の要求と整合することを確認して差し替える。処理途中のキャンバスを露出させず、差し替え時に表示位置を動かさない。
5. 領域単位での段階的な差し替えを認める。各領域の準備が完了するまでは対応する暫定画像を残し、画面全体が白くなる切り替えを避ける。現在と異なるページや編集状態の画像は代用しない。
6. 再操作で古くなった要求は中断または優先度を下げ、古い完了結果によって最新の表示を上書きしない。操作が落ち着いたら表示範囲全体の高精細化を必ず再予約する。

- 拡大縮小はマウスポインター位置、ツールバーからの操作は表示領域の中央を基準にし、見ていた図面上の位置を維持する。
- Ctrl+ホイールで拡大縮小、Space+左ドラッグまたは中ボタンドラッグでパンできる。文字入力中はSpaceをパン操作として扱わない。
- 高精細化に時間がかかる場合は控えめに「高精細化中」を表示する。暫定画像だけの状態を描画完了と扱わない。

### 6.3 大判図面と描画メモリ

- A0・A1などの大判図面を高倍率で開く場合は、表示範囲とその周囲だけを高精細化する。低解像度のページ全体像と、高解像度の詳細領域を組み合わせる方式を基本とする。
- PDF.jsの詳細領域描画を採用バージョンで評価し、要件を満たす場合は活用する。必要に応じて領域をタイルに分割する。描画方式自体は固定せず、画質・応答性・メモリの受け入れ条件を満たす方式を選ぶ。
- 表示範囲外には小さな余裕を持たせ、近傍や移動方向を先読みする。広範囲の先読みで現在見ている領域の処理を遅らせない。
- タイルを用いる場合は境界に描画の余白を設け、同じ座標変換とピクセル基準で切り出す。透明度や線幅が境界で変わらないようにする。
- 優先順位は、現在の画面の即時追従、表示範囲の高精細化、近傍の先読み、サムネイル・検索準備などの順を基本とする。検索操作中は検索にも必要な実行時間を割り当てる。
- キャッシュは文書ID・編集状態・ページID・回転・描画倍率・ピクセル密度・領域を区別する。最近使ったものを残す方式と容量上限を併用し、非表示タブ・画面外領域から解放する。
- キャッシュ、描画中と表示中の二重バッファ、画像デコード、GPU資源を含む負荷を測定する。キャンバスの単辺・総面積上限も確認する。
- メモリ不足時は先読みとキャッシュ量を先に減らし、詳細領域の縮小・分割や描画並列数の削減で対応する。メモリ上限を理由に最終表示を一律低解像度へ固定しない。
- 品質を満たせない描画エラーは再試行できる状態で明示する。暫定画像を無言で最終表示として扱わない。

## 7. 全文検索

- 現在のタブの全ページに含まれる文字を対象とする。
- 検索結果はページ番号と前後の短い文脈を表示し、クリックで一致箇所へ移動する。
- 本文の一致箇所を強調し、現在の一致を別の強調で示す。
- Enterで次へ、Shift+Enterで前へ。先頭・末尾を循環する。
- 初期設定は大文字小文字を区別しない。区別する設定も用意する。
- PDF.jsの文字抽出・検索を基盤に、改行をまたぐ語句や日本語の分割文字列を検証する。
- 検索準備はバックグラウンドで進め、処理中は進捗と暫定件数を表示する。完了前に「一致なし」と断定しない。
- 検索語の変更・タブ終了時に古い検索を中断し、古い結果を反映しない。
- 削除済みページは検索から除外し、並べ替え後は現在のページ順で結果を並べる。
- 文字を含まないスキャンPDFには「検索できる文字情報がありません」と表示する。OCRは行わない。

## 8. ページ編集と保存

### 8.1 並べ替え・削除・回転

- 同じPDF内のページの順序を変更する。
- 選択ページの削除と、左右90度単位の回転に対応する。回転は表示だけでなく保存結果にも反映する。
- 全ページの削除はできない。最後の1ページを残すよう案内する。
- 一括操作は1回の「元に戻す」で戻せる。新しい編集後はやり直し履歴を破棄する。
- 編集中は元PDFを保持し、ページID・元ページ番号・回転角度の一覧として編集状態を管理する。各操作でPDF全体を書き直さない。

### 8.2 保存

- 初期版は「名前を付けて保存」を基本とする。Ctrl+Sも保存先の選択を開く。
- 初期ファイル名は `元の名前_編集.pdf`。元ファイルへの自動上書きは行わない。
- ユーザーが既存ファイルと同じパスを明示指定した場合は、置き換え確認後に保存する。
- 保存は一時ファイルへの書き込みと検証を経て置き換える。失敗時に既存ファイルや編集状態を失わない。
- 保存成功後は出力ファイルを現在のタブで開き直し、未保存状態と編集履歴をリセットする。元ファイルはディスクに残す。
- 編集済みタブを閉じる際は「保存／破棄／キャンセル」を表示する。アプリ終了時も同じルール。
- 権限不足・ディスク容量不足・ファイル使用中などは日本語で表示し、別の保存先を選び直せる。
- 元ファイルの外部更新を検出した場合は通知し、未保存編集を自動破棄しない。

## 9. 結合・分割

### 9.1 結合

- 複数PDFを選択し、ファイル一覧を並べ替え、各PDFの全ページを指定順に結合する。
- 一覧にファイル名・ページ数を表示し、追加・除外に対応する。
- 元ファイルは変更しない。出力名の初期値は `結合.pdf`。
- 入力はディスク上の保存済みPDF。開いているタブの未保存編集は自動で取り込まないことを画面に明示する。
- 結合結果は保存後に新しいタブで開く。
- 処理中は進捗を表示する。キャンセル時は結果を保存しない。

### 9.2 分割・ページ抽出

- 現在のPDFのページ範囲、またはサムネイルで選択したページを新しいPDFとして保存する。
- 入力例：`1-3, 5, 8-10`。カンマ区切り・ハイフン範囲を受け付け、空白は無視する。
- 出力順は現在のPDFのページ順。重複指定は1回にまとめる。
- 範囲外・逆順範囲・不正な文字は保存前に示し、黙って補正しない。
- 初期版の「分割」は指定ページを1つの別PDFに抽出する機能とする。全ページの個別ファイル化や範囲ごとの一括出力は対象外。
- 未保存の並べ替え・削除・回転も反映する。抽出しても現在のPDFからページは削除しない。
- 保存後に結果を新しいタブで開く。元タブの編集状態は保持する。

## 10. 印刷

### 10.1 利用者向け動作

- 印刷ボタンまたはCtrl+Pで、現在のPDFを印刷するためのWindows標準印刷ダイアログを開く。
- プリンター選択、部数、ページ範囲、用紙、方向などは、標準ダイアログとプリンタードライバーが提供する設定へ委ねる。
- 両面、カラー、トレイ、製本などは、選択したプリンターとドライバーが対応する場合に設定できる。全機種で同じ項目を保証しない。
- アプリ独自の詳細設定画面と印刷プレビューは作らない。
- 未保存のページ順・削除・回転も印刷に反映する。準備開始時点の文書状態を固定し、その後の編集と混在させない。
- 準備中は状態を表示する。キャンセルは通常の中断として扱い、失敗と区別する。
- 印刷ジョブを渡した後は「プリンターに送信しました」と表示する。実際の紙への出力完了までは判定しない。

### 10.2 実装方針と事前検証

- Electronの `webContents.print({ silent: false })` を入口の候補とする。
- 閲覧画面そのものは印刷せず、ページごとの印刷専用文書を用意する。
- 紙面サイズとページ区切りを保持する。画面用の低解像度サムネイルは使用しない。
- PDF.jsで印刷用の描画を作る方式を第一候補とする。大きなPDFでのメモリ負荷を測定し、準備完了を待ってからダイアログを開く。
- 「ドライバーに任せる」場合も、アプリ側で正しいページ内容・サイズ・解像度を渡す必要がある。
- 標準ダイアログからのドライバー詳細設定への到達、ページ範囲、倍率、回転、混在用紙サイズの扱いを最初の試作で検証する。
- 上記が満たせない場合は、アプリ内部に同梱するPDF印刷用の補助実装を検討する。既定PDFビューアへの関連付けに依存する方式は採用しない。
- 印刷方式は技術検証で確定する。新たな外部バイナリを採用する場合は配布条件・サイズ・ライセンスを確認する。

## 11. 復元と設定

- ファイルごとに最後のページ、ページ内の位置、表示倍率・表示方式を保存し、再度開いたときに復元する。
- アプリ終了時のタブ、ウィンドウ配置、選択タブを保存し、次回起動時に復元する。設定で無効化可能。初期値は有効。
- 多数のタブがある場合は選択タブを優先し、他のPDFは選択時に読み込む。
- OSから新しいPDFを指定して起動した場合は、そのPDFを最優先で表示し、前回セッションの読み込みで待たせない。
- 画面外に保存されたウィンドウ位置は、現在のディスプレイ内へ補正する。
- 移動・削除されたファイルは一覧で知らせ、他のファイルの復元を継続する。
- 最近開いたファイルは最大20件。履歴の消去に対応する。
- 初期版は未保存編集のクラッシュ復旧を保証しない。通常終了時の保存確認と、保存済みPDFの閲覧状態復元を対象にする。
- 設定・閲覧履歴はユーザーデータ領域に保存する。パスワードを保存しない。
- 外観設定はアプリ全体で共有し、セッションの復元設定とは独立して保持する。

## 13. PDFの互換性

- 一般的な文字・画像を含むPDFを主対象とする。
- パスワード付きPDFはPDF.jsで対応可能な範囲の閲覧に対応し、パスワードを都度入力する。暗号化PDFの結合・分割・編集保存は初期版では対応しない。
- 文書の印刷・コピー等の権限情報を確認し、許可されない操作は無効化する。
- 破損PDF・未対応形式は理由を表示し、他のタブを継続利用できるようにする。
- 電子署名の検証・維持は対象外。署名付きPDFの編集保存は初期版では無効化する。
- 既存のしおり、フォーム、注釈、添付ファイル、タグ、内部リンク等の完全な保持は編集出力で保証しない。ページ構成の変更で影響する情報を含む場合は保存前に案内する。
- 原本の閲覧と、ページ編集後の出力の互換性を分けて検証する。

## 14. 内部構成

| 要素 | 役割 |
| --- | --- |
| Electronメインプロセス | ウィンドウ、起動引数、ファイルアクセス、保存、印刷、設定 |
| preload | 型付き・用途限定のAPIをReact側へ公開 |
| React + TypeScript | 閲覧UI、タブ、検索UI、ページ整理UI |
| PDF.js | PDF描画、文字抽出、検索、サムネイル、印刷用描画 |
| pdf-lib | ページコピー、回転、結合・抽出・編集PDF生成 |
| Worker等の分離実行 | PDF解析・検索・編集出力などの重い処理 |

- UI構築はViteを利用する。依存バージョンは実装開始時に互換性を確認し、ロックファイルで固定する。
- 各文書に文書IDと編集リビジョンを持たせる。検索・描画・保存の非同期結果が古い状態へ戻さないよう検証する。
- ウィンドウ移動中も文書状態の所有者を一意にし、転送失敗時は元ウィンドウを維持する。
- PDFのバイナリをタブ切り替えや各編集のたびにプロセス間で複製しない。
- 非表示タブのキャンバスと遠いページの描画キャッシュを解放する。
- 描画スケジューラーで優先度・同時実行数・キャンセル・キャッシュ予算を管理する。PDF解析のWorker化だけで画面描画まで分離できるとは仮定せず、メインスレッドの長時間占有も測定し、分割実行や対応可能な描画の分離を検討する。
- 保存・結合・印刷に使用する一時ファイルは終了後に削除する。異常終了後の残存分も次回起動時に清掃する。

## 15. セキュリティとプライバシー

- `nodeIntegration: false`、`contextIsolation: true`、サンドボックスを有効にする。
- レンダラーへ任意のファイル操作や任意IPCの実行を公開しない。
- IPCの呼び出し元・引数・文書ID・対象パスをメイン側で検証する。
- PDF内のJavaScriptは実行しない。外部ページのアプリ内遷移や無断のウィンドウ生成を禁止する。
- CSPを設定し、実行コード・フォント・PDF.js関連資材はローカルに同梱する。
- 広告、アクセス解析、文書内容の収集は行わない。

## 16. 性能目標と測定方法

以下は保証値ではなく初期の受け入れ目標。測定環境はWindows 11 / SSD / メモリ16GBの実機とし、CPU型番・アプリ版・PDFを記録する。開発サーバーではなく配布用ビルドで測る。

| 項目 | 目標 |
| --- | --- |
| 通常PDFの初回ページ表示 | 10MB以下・50ページ程度の文字中心PDFで、起動要求から3秒以内を目指す |
| 既存ウィンドウでPDFを開く | 同じPDFで操作から初回ページ表示まで1.5秒以内を目指す |
| 一般的なUI操作 | タブ選択やメニュー表示などの視覚応答を100ms以内に開始 |
| ズーム・パンの追従 | 高精細描画を待たず100ms以内に視覚応答を開始し、一般的な図面で60fpsを目標とする |
| 高精細化の完了 | 読み込み済みの通常図面では操作停止から表示範囲全体の更新まで1秒以内、複雑な大判図面では3秒以内を初期目標とし、未達を個別に記録する |
| 大きなPDF | 500ページ程度で全ページの同時描画を避け、処理中もUIが反応する |
| メモリ | タブ終了後にバッファ・キャンバスを解放し、開閉の繰り返しで増え続けない |

- コールド起動とウォーム起動を分けて各5回測定し、中央値と最大値を残す。
- 最初のページ表示を全ページのサムネイル・文字抽出の完了待ちにしない。
- 画像中心PDF、大判図面、フォントの多いPDFは別ケースとして記録する。
- 描画の品質・応答性はA3・A1・A0のベクター図面、スキャン図面、ベクターと画像の混在図面で測定する。25〜1600%の代表倍率、4K表示、OS表示倍率100・150・200%、回転時とモニター間移動を含める。
- 入力から最初の視覚応答までと、最後の入力から表示範囲全体の高精細化完了までを別々に記録する。キャッシュあり・なしを分け、中央値と95パーセンタイル、最長のフレーム停止時間、メモリピークを記録する。95パーセンタイルの評価は各代表ケースで20操作以上を目安とする。
- 高精細化完了は、表示範囲の全領域が現在の倍率・ピクセル密度に対応する描画へ置き換わった時点とする。フォント・画像の読み込み待ちや暫定画像の表示時間を除外しない。
- 同じPDF・範囲・倍率・ピクセル密度の単独高精細描画を基準に、差し替え後の画面で細線・文字・ハッチング・境界を比較する。基準自体の誤描画は別のPDFビューアとの比較でも確認し、ぼけ・欠落・継ぎ目を速度改善の代償として許容しない。
- 印刷準備・結合・保存のメモリピークと所要時間も記録する。
- 性能目標を満たさない場合は処理の測定結果から改善し、常駐による見かけの高速化は初期方針にしない。

## 17. 受け入れ確認

1. インストール後、PDFのダブルクリック・複数ファイルドロップで開ける。
2. 50ページのPDFでサムネイルと本文の現在ページが一致し、クリック移動できる。
3. 日本語・英語の全文検索で一致強調と前後移動ができる。検索中もスクロールできる。
4. 複数選択での並べ替え・削除・回転と、元に戻す・やり直すが正しく動く。
5. 編集を含むタブを別ウィンドウへ移し、戻しても状態と履歴が失われない。
6. 編集・結合・抽出したPDFを別のPDFビューアで開き、ページ数・順番・回転・表示を確認できる。
7. 保存をキャンセル・失敗しても原本と未保存編集が残り、閉じる際に保存確認が出る。
8. 実プリンターとMicrosoft Print to PDFで、ページ範囲・用紙・方向・ドライバー詳細設定を検証する。実機対応時は両面印刷も確認する。
9. 未保存編集を反映した印刷、印刷キャンセル、プリンターエラーを区別できる。
10. A4・A3・縦横混在PDF、細い罫線、日本語、画像で、印刷の切れ・欠落・著しいぼけがないことを確認する。
11. 再起動時にタブ・ウィンドウ・ページ位置を復元する。ファイル欠落時も起動できる。
12. パスワード付き、破損、署名付きPDFの制限を適切に表示する。
13. 参考画像に沿う色・余白・線・ボタンを画面確認し、100〜200%の表示倍率で操作が隠れない。
14. 起動・初回描画・大容量文書・反復開閉を配布用ビルドで測定する。
15. ライト・ダークの全画面で文字・アイコン・検索強調・フォーカスが判別でき、表示倍率100〜200%でも操作できる。
16. テーマの手動切り替えとOS追従が全ウィンドウへ反映され、再起動・新規ウィンドウでも保持される。
17. ダークでもPDF本文とサムネイルの元の色が保たれ、保存・印刷結果がライト時と変わらない。
18. ベクター図面の400・800・1600%表示で、操作停止後に線と寸法文字が現在の倍率相当の精細さになり、低解像度画像の引き伸ばしが残らない。
19. 急速な拡大縮小・往復パン・ページ移動を繰り返しても、古い描画への巻き戻り、異なるページの混入、画面全体の白抜け、差し替えに伴う位置ずれが起きない。
20. 大判図面の詳細領域・タイル境界で、細線・破線・透明なハッチングに切れや二重線がない。検索強調・文字選択も本文と一致する。
21. 4K表示や異なる表示倍率のモニターへの移動後に再描画され、画面密度に見合う精細さになる。
22. 長時間のパンとズーム、複数タブ・ウィンドウでの使用でもメモリが増え続けず、操作停止後の高精細化が必ず完了する。エラー時は理由と再試行を表示する。
23. スキャン図面は元画像の情報を保持し、ベクター図面と同等の細部復元を保証していないことを確認する。

## 18. 実装順序

1. 技術検証：大判図面の高倍率・詳細領域描画、暫定表示からの差し替えとキャンセル、画質・応答性・メモリ測定、印刷ダイアログとドライバー連携、起動時間測定。
2. 基盤：Electronの安全な構成、ファイルオープン、タブとウィンドウ、rediaに合わせたUI。
3. 閲覧：サムネイル、移動、ズーム、検索。
4. 編集：ページ整理、保存、結合・抽出、元に戻す。
5. 日常利用：関連付け、復元、エラー処理、配布、実機検証。

初期版は上記すべてを対象とする。実装順序は機能を後回しのまま完了とする意味ではない。
